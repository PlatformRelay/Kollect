### 2-4. gobreaker v2.4.0 (verified by reading and by a scratch probe)

Source: `$(go env GOMODCACHE)/github.com/sony/gobreaker/v2@v2.4.0`.

- `afterRequest` checks `isExcluded` first and returns after `onExclusion` (`gobreaker.go:264-266`);
  `onExclusion` → `rollingCounts.onExclusion` → `Counts.onExclusion`, which only increments
  `TotalExclusions` (`counter.go:32-34,106-115`). `ConsecutiveFailures` is neither incremented nor reset;
  `readyToTrip` is not evaluated.
- Half-open admission: `cb.counts.validRequests() >= cb.maxRequests` → `ErrTooManyRequests`
  (`gobreaker.go:246`); `validRequests = Requests - TotalExclusions` (`counter.go:36-41`). An excluded trial
  therefore frees the slot; the state does not change (no `setState` on exclusion).
- With `Interval > 0` and no `BucketPeriod`, there is one bucket (`gobreaker.go:133-136`); entering closed
  sets `expiry = now + interval` (`gobreaker.go:355-359`); `currentState` starts a new generation when it
  expires (`gobreaker.go:306-308`), clearing all counts (`toNewGeneration`, `gobreaker.go:348-351`).
- Results from an earlier generation are dropped (`gobreaker.go:259-262`).
- `Counts()` returns the stored counts without calling `currentState` (`gobreaker.go:205-210`); read
  `State()` first when a test asserts counts after a time step.

Probe (scratch module outside the repository, run 2026-11-05 with
`GOFLAGS=-mod=mod GOPROXY=off GOWORK=off go run .`, repo `go.sum` copied in; same `ReadyToTrip`/`MaxRequests`
