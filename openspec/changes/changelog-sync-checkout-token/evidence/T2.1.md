## What the guard checks (section 6, `credential_errors` in `syncwf.py`)

- Every `actions/checkout@` step: no `token` key under `with`; `persist-credentials` is `false`
  (boolean or the string `"false"`); absent counts as `true`, the action's default.
- Every `actions/create-github-app-token@` step has an `id`, and no step except the push step has
  a string matching `steps.<id>.outputs` or `steps['<id>'].outputs`, anywhere in the step (`with`,
  `env`, `run`, `if`).
- Section 8 adds four mutants and one honest variant. It also fixes a pre-existing defect:
  `mutation_took_effect ... || return` returned 1 under `set -e`, so the first no-op mutant ended
  the run before the remaining cases and the summary. It now returns 0 after `fail()` has counted
  the failure.

The guard has a single mode. The self-test (section 8) runs on every invocation, so "both modes"
is one command here.

## Limitations

- Structural only. The live proof that the push works without the checkout token is the
  post-merge changelog-sync run (tasks.md 4.2).
- A token reaching another step through a renamed output, an action that reads it implicitly, or
  `steps.*` is not detected. The check matches `steps.<id>.outputs` (dot or bracket),
  `toJSON(steps)` and the App secret names.
