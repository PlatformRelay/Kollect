# T1.1 — probe: how changelog-sync pushes, and who uses the checkout's credentials

- Revision: `origin/main` at `a9913eda9` (file unchanged by `950743808`) · 2026-10-16
- Method: read `.github/workflows/changelog-sync.yaml` end to end, the tasks and scripts it calls,
  and the logs of recent runs on `main`.
- Verdict: **removing `token:` from the checkout does not affect the push.** Not BLOCKED.

## Findings

1. The push authenticates itself. It reads the App token from its own `env` (line 120) and builds
   the `AUTHORIZATION: basic` header in `GIT_CONFIG_VALUE_0` (line 136); it does not read
   `.git/config` credentials. No other step pushes, fetches or calls `gh`.
2. Nothing after the checkout can rely on the checkout's credentials, because none survive it:
   with `persist-credentials: false` the action removes its extraheader after the fetch. The log
   of run 38551429146 shows the cleanup ("Removing HTTP extra header",
   `git config --local --unset-all 'http.https://github.com/.extraheader'`).
3. git-cliff (`Taskfile.yml:384-388`, `hack/release/cliff.toml:4-6` `[remote.github]`) calls the
   GitHub API for PR numbers. It never received the checkout's token: the Regenerate step's env is
   `CI` only, and git-cliff reads `GITHUB_TOKEN` from the environment, not git credentials. So its
   API calls are unauthenticated today and stay unauthenticated after this change.
4. The repository is public and the job grants `contents: write` (lines 71-72), so the default
   `GITHUB_TOKEN` can fetch full history and tags.
5. The push path works today: run 38889827962 (headSha `7ced03a7e`) pushed `7ced03a7..0181e717
   HEAD -> main` and logged "Pushed regenerated CHANGELOG.md to main."

## Out of scope, found by the probe

Run 38551429146 (headSha `0c1456b5d`, 2026-10-14) failed in "Regenerate CHANGELOG.md": git-cliff
panicked with `Could not get github metadata: HttpClientError(... Status(403) ...
/repos/platformrelay/kollect/commits?per_page=100&page=20)`, which is the unauthenticated API rate
limit (finding 3). This change neither causes nor fixes that; passing `GITHUB_TOKEN:
${{ github.token }}` to the Regenerate step would. It is not part of CST-1.

## Limitations

The probe is a reading of the workflow and of run logs. The live proof that the push still works
without the checkout token is the post-merge changelog-sync run (tasks.md 4.2).
