## Notes

- Driver errors still carry hosts (for example the ping error `Addr: sentinel-host:27017`): a
  known follow-up, out of scope (spec SCT-3 narrows the rule to the errors this change adds; loop
  *Triage* R1).
- `tlsAllowInvalidCertificates` and `tlsAllowInvalidHostnames` are not options mongo-driver
  v1.17.10 reads (`connstring.go` puts them in `UnknownOptions`); a value other than `false` is
  still rejected next to a CA, because it asks for less verification than `spec.tls` gives
  (dispatch). The driver's effective `tlsInsecure` is last-value-wins, so `true` then `false` is
  accepted, as the driver reads it.
- An SRV URI's TXT record cannot turn TLS off or name a CA file: the driver allows only
  `authSource`, `replicaSet` and `loadBalanced` there (`x/mongo/driver/dns/dns.go:136-138`).
- The URI check runs in `clientOptions`, which build (`backend.go`) and probe
  (`connection.go`) both call, not in `ConfigFromSpec` as the design sketch put it and 4.2's file
  list implies (`config.go` is unchanged): `ConfigFromSpec` has no `caPEM` and no caller outside
  the package, and one shared function gives probe and export the same error (SCT-5 *Probe and
  export agree*). Behaviour is what SCT-3 asks: rejected at backend build, before any connect.
- With a CA, `clientOptions` calls `Validate` after `ApplyURI` so a driver parse error is reported
  as `mongodb connect: …` (as `mongo.Connect` would) rather than as a nil TLS config.

## Maintainability

1. Locality: yes; outside the MongoDB package only the two call sites and the test helper.
2. Change surface: ~250 lines of product code, most of it the DNS-free URI reader the driver does
   not export (its parser type with a pluggable resolver is unexported, probe 0.1).
3. Duplication: the reader mirrors `connstring.parse`/`addOptions` for the TLS keys only; a test
   compares it with the driver on a table, so drift on a driver bump shows as a red test.
4. Second way: no new knob.
5. Coupling: the package now knows which driver options turn TLS on; the backstop on the
   driver-built config catches what the reader misses.
6. Abstraction: uses `sinktls.AppendedPool` and the shared error style of G3.
7. Debt for green: none; the two-second test deadline only bounds an unexpected connect.
8. Legibility: one function per design step (`checkCAURI`, `checkDriverTLS`, `clientOptions`).

## Learnings

- class: sensor.
- G4: mongo-driver has no DNS-free parse; prove "no lookup" by swapping
  `dns.DefaultResolver.LookupSRV`/`LookupTXT` for functions that fail the test, in a serial test
  that goes through the real build path (a check function with no DNS code proves nothing).
- G4: a reader that mirrors a library parser needs a differential table against the library on
  the URIs the library refuses too; a mutation survived until the table held an `@` in the query
  with no user info.
