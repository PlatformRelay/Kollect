2. Change surface: ~330 lines of product code for SCT-2; most is the DSN key reader that mirrors

   exported equivalent, so the copy is deliberate and commented with the source.
4. Second way: no new knob; the DSN reader exists only to read four keys before pgx parses.
5. Coupling: `postgres` now knows pgx's settings precedence (env < service < DSN, home default);
   that knowledge is what SCT-2 asks for, with the parsed-config backstops for anything it misses.
6. Abstraction: uses `sinktls.AppendedPool` and the existing redaction helpers.
7. Debt for green: the 200 ms pipe deadline is test-only timing, not product behaviour.
8. Legibility: one function per design step (`caDSN`, `applyCA`), each with its rule in the comment.

Easier next: MongoDB (G4) can reuse the container helper pattern and the error style. Harder: a
pgx bump that changes settings precedence must be checked against `caDSN`.

## Learnings

- class: sensor, guidance.
- G3: a hand-written mirror of a library parser drifts on presence-versus-empty and on syntax
  corners (bracketed hosts); test the reader's own output against the library's on a table of
  edge spellings, and back it with a post-parse shape check.
- G3: `net.Pipe` is unbuffered: a TLS peer that rejects the certificate deadlocks against the
  server's flight until the context ends; give the server end a short deadline.
- G3: `go test` under umask 002 makes `t.TempDir()` 0775 and fails `internal/sink/git`'s mirror
  guard; run suites with `umask 022`.
