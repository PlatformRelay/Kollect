## Interface

`hack/ci/fuzz-retry.sh <FuzzTarget> <pkg>` (mode 100755). Diagnostics, each a whole line:

| Line | When |
| --- | --- |
| `::error::fuzz-retry: deny marker <marker>` | the output holds `panic:`, `fatal error:`, `Failing input written` or `signal: killed` (checked in that order, before the exit status: an attempt that exited 0 fails too) |
| `::error::fuzz-retry: unrecognised failure text` | non-zero exit and the non-`fuzz:` lines are not the flake sequence; or exit 0 with no `fuzz: elapsed` and no zero-target warning |
| `::error::fuzz-retry: no fuzz target ran` | exit 0, no `fuzz: elapsed`, `no fuzz tests to fuzz` |
| `::error::fuzz-retry: git status failed` | the flake, and `git status --porcelain --untracked-files=all` fails |
| `::error::fuzz-retry: crash corpus under testdata/fuzz/` | the flake, and a status path holds `testdata/fuzz/` |
| `::error::fuzz-retry: deadline flake on both attempts` | the flake on attempt 2 |
| `::error::fuzz-retry: usage: fuzz-retry.sh <FuzzTarget> <pkg>` (exit 2) | not two arguments, or the target is not `Fuzz[A-Za-z0-9_]*` |

The retry logs `::warning::fuzz-retry: <target> hit the fuzz engine's "context deadline exceeded"
flake at the -fuzztime boundary (golang/go#75804) on attempt 1; retrying once`.

## Learnings

- tooling: `gh run view <run> --log --job <id>` ignores the run id; list the run's jobs first
  (loop.md *Lessons*).
- sensor: exactly-once literal mutant anchors collide with comments that repeat a flag; keep each
  mutated clause on one line at one site (loop.md *Lessons*).
- sensor: a CFC-6 "did not apply" probe must grep the step text, not the guard name (loop.md
  *Lessons*).
- sensor: every exit path needs a case, the success path included: the deny markers sat after
  the exit-0 branch and no case replayed a marker with exit 0 (loop.md *Lessons*).
- spec: an exact-output allow-list must name every line class the command can print on the path
  it guards (here `go: downloading` on a cold cache); proposed to the orchestrator.
