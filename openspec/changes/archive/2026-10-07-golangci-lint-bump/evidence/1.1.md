## Learnings

- tooling: reading a long sensor log through `tail` truncates the finding list — the first
  full-gate markdown run showed 4 of 7 errors and that wrong count propagated into evidence
  until review caught it. Capture the full output to a file first, grep it second (persisted:
  loop.md Lessons; proposed as a standing guidance line for this loop's next tasks).
- tooling: `make golangci-lint`'s freshness check breaks when `bin/golangci-lint` is left as a
  plain file (post-`mv` from the custom build): the next `make golangci-lint` (e.g. inside
  `task format:check`) silently re-runs the full install + custom build (~40 s warm). Harmless
  in a probe; worth knowing before task 1.2 commits the pins (persisted: loop.md Lessons).
- tooling: golangci-lint's `config verify` does NOT validate custom-plugin linter registration —
  the vanilla-build failure surface is `run` (build linters, exit 3). Evidence wording should
  say run-start, not config validation (corrected in probe.md §4; tasks.md 1.1/1.3 wording says
  "config validation" — the spec claim still holds via the structural proof, but 1.3's
  phrasing may deserve the same correction; recorded for the spec-loop orchestrator).
