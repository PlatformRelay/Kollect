## Learnings

- tooling: golangci-lint's `uniq-by-line` (default true) hides goconst findings on lines
  that already carry one — a "0 findings" gate can be measured against a truncated set;
  size goconst work with `--uniq-by-line=false` (persisted here; proposed as a change-5
  CI check).
- tooling: jgautheron/goconst v1.11.0 emits one issue per (string, file) at the string's
  first position in that file, counts only non-`Call`-type literals (direct call args are
  excluded by default `ExcludeTypes: [Call]`), and const declarations never count as
  occurrences — so a constant may share a value with another constant freely
  (find-duplicates off) without re-triggering goconst.
- tooling: controller-runtime v0.24 queues `Requeue:true` via AddRateLimited (exponential
  backoff, Forget on success) and `RequeueAfter` via a fixed `AddAfter` delay that also
  Forgets — the migration from the deprecated field is a real policy choice, not a
  mechanical rename; per-site justification is required.
- process (task-level): a focused sensor run that times out on one package must not be
  silently dropped from the record — the git package's 480s timeout hid the controller
  test corrections until the full-suite run caught them.
- tooling: zizmor is not preinstalled locally; `bash hack/install-zizmor.sh <dir>` (into
  an out-of-repo temp path) reproduces the CI-pinned 1.30.1 offline audit in seconds.
