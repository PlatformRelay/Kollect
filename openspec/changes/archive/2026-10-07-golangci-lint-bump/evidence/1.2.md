## Learnings

- tooling: `go version -m <custom-built-golangci-lint>` lists the resolved plugin module
  version (`dep sigs.k8s.io/logtools v0.10.1 …`) — a one-command sensor that retires the
  "which version did the plugin build use" believed-claim; use it for future plugin-pin tasks
  (persisted: loop.md Lessons; proposed to change 5, developer-toolchain-pins, as the cheap
  drift check next to DTP-3).
- tooling: go-task 3.51.1 exits **201** whenever a task's command fails, printing the inner
  command's code (`exit status 2`) only in the message — record the wrapper code, or read the
  message, but never mix the two conventions across records (the probe's "task exit 2" and
  this task's 201 are the same failure).
- tooling: the stale-`bin/golangci-lint`-target hazard has two faces: make skips when the
  binary is already current (observed twice today) and also skips after a pin-only edit —
  `rm -f bin/golangci-lint*` before `make golangci-lint` remains the only reliable way to
  prove a build from the committed pins (persisted: loop.md round-2 finding 7 deferral).
