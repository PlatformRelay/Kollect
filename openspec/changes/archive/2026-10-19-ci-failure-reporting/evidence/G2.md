## Interface (fixed here; 3.3 calls it)

```text
hack/ci/ci-failure-issue-body.sh --workflow-name <name> --workflow-path <path> --run-id <id> \
  --run-url <url> --key <run_number>.<run_attempt> --jobs <jobs.json> [--log <failed.log>]
```

Exit 0 with the body on stdout; exit 2 with nothing on stdout on a bad argument or unreadable jobs
JSON. Only `event=failure` bodies are built: the recovery comment is 3.3's, which may add an
`--event` option with its own case. Decisions taken here, each from spec.md CFR-5 or T1.1:

- failed job = conclusion not `success`, `skipped` or `neutral` (T1.1 F7); failed step = first step
  with such a conclusion, from the jobs JSON, never the log (T1.1 F4: every log line says
  `UNKNOWN STEP`);
- `FAIL` line = a log line containing `FAIL` (matches `--- FAIL:`, `FAIL\t` and the nightly's
  `FAILURE:`), the first 50 in log order, verbatim apart from a trailing CR;
- `@` outside a fence becomes `@&#8203;` (zero-width space entity); `&` and `<` become entities
  and control characters spaces, each field cut at 200 characters before escaping (`>` is left as
  is: without `<` it opens no tag or comment, and a field never starts a line);
- lengths are counted in bytes (`LC_ALL=C`), never fewer than characters, so `< 60000` bytes
  implies `< 60000` characters; excerpt lines are cut at 4000 bytes, dropping a partial UTF-8
  sequence at the cut;
- the four marker inputs are validated (path `^\.github/workflows/[A-Za-z0-9._-]+\.ya?ml$`,
  positive integer run id, `N.M` key, `https://github.com/<o>/<r>/actions/runs/<id>[/attempts/<n>]`),
  so no input can end the comment or add a field. Case 11 (four refusals) is added beyond 2.1's
  list for this.
- a job list that alone would not leave room for one excerpt line exits 2 rather than cut the
  list (case 13; not reachable with this repository's 11 job entries);
- a log that exists but cannot be read (`grep` exit 2) is "logs unavailable", like an absent or
  empty one;
- the builder lists every failed job of a run it is given. CFR-1 decides whether a run is reported
  at all (run conclusion only), so a `continue-on-error` job such as `race (advisory)` never
  produces a report by itself; when the run failed for another reason, it is listed too, because it
  did fail (opus round 2, recorded as a decision, not a defect).

## Learnings

- A size-cap case must make the input too big to fit uncut, or a removed cut passes it (G2)
- The test's own Markdown oracle needs a fixed-text control case, or it can accept malformed fences (G2)
- Escaping each character class needs its own killing case: three escapes passed 15/15 when deleted (G2)
