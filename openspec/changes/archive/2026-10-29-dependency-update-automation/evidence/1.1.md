## Design choices

- **Self-test runs on a fixture, not the real tree.** `--self-test` copies `.github/` from the
  root, replaces `renovate.yaml` with a known-good workflow written in the guard (hourly
  `17 * * * *`, `concurrency` `renovate` / `false`, `permissions: contents: read` at workflow and
  job, the fail-closed token step, `renovatebot/github-action@2804199d260ad00c1fae0e9e842888369391c776 # v46.3.10`,
  `renovate-image` `ghcr.io/renovatebot/renovate:44.179.1@sha256:f30ad41a…`, token
  `secrets.RENOVATE_TOKEN`, `configurationFile` `.github/renovate-config.json`,
  `RENOVATE_REPOSITORIES`, `LOG_LEVEL` debug on dispatch; the shape of `evidence/0.4.md`'s planned
  workflow, pins from `evidence/0.4.md` (d) and `evidence/0.5.md`), and rewrites `ci.yaml`'s lint
  job to hold exactly one `bash hack/ci/renovate-config-validate.sh` step. Reason: today's tree is
  red on T1 to T8, so a mutant of the real tree would not prove its own clause; the fixture is
  green now, stays green after 2.1 and 2.3 land (it never reads the real `renovate.yaml` or the
  real validator step), and a bot bump of the real pins cannot turn it red. Every other workflow
  is the real one, so T9's no-op control also covers today's real workflows.
- **Extensible for 1.2.** Clauses are functions listed in `CLAUSES`; mutants are functions listed
  in `MUTANTS` as `clause|function|expected message`; `FIXTURE_PATHS` names what the fixture
  copies. 1.2 appends T10 to T17 to those three lists.
- **Judging.** Plain mode runs every clause and prints `FAIL: Tn: <message>` per violation. In
  `--self-test`, a mutant passes only if the guard exits non-zero, a `FAIL: <clause>:` line matches
  its expected message, and no `FAIL:` line of any other clause appears. One row, `T2+T7`, also
  allows T7 (see T7 below).
- **T2 runs the body.** The token step's parsed `run:` body is run the way the runner runs it:
  `bash -e` when no `shell:` is set (step, job or workflow default), `bash --noprofile --norc
  -eo pipefail` for `shell: bash`; in a temp dir with `env -i`, stdin closed, `timeout -k 5 20`;
  once with `RENOVATE_TOKEN` empty (must exit non-zero and print `RENOVATE_TOKEN`) and once with
  a dummy non-secret value (must exit 0). Any other `shell:` is refused.
- **Beyond the task text, all stricter:** T1 also matches `github['token']` and
  `secrets['GITHUB_TOKEN']`, case-insensitive; T3 refuses absent effective permissions (the
  default token can write); T7 scans `RENOVATE_*` keys at any depth (not only `env:` maps),
  refuses an `env:` that is not a mapping (an expression could inject any variable), and refuses
  `GITHUB_ENV` in any parsed string (not only `run:`), and requires `RENOVATE_REPOSITORIES` to be
  exactly `${{ github.repository }}`; T6 requires `configurationFile` to be exactly
  `.github/renovate-config.json` (the global config 1.2's T13 checks); T9 reads `on:` in map,
  list and string form, also scans composite actions under `.github/actions/`, also refuses
  `mergePullRequest`, and reds a file it cannot read.
  T7 allows `RENOVATE_TOKEN` only in the `env:` of one `run:` step without `uses:` before the
  Renovate step in its job (the T2 step), so moving the check after Renovate reds T2 and T7;
  that one mutant row is `T2+T7`.
