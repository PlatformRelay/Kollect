## Maintainability

1. Locality: yes, one new guard plus this change's records.
2. Change surface: one ~830-line guard for about 30 case groups; most lines are mutants.
3. Duplication: the copy-and-run harness repeats the pattern of the sibling guards, adapted to a
   git-repository copy; no shared helper exists to reuse.
4. Second way: `AGENT_CONTRACT_ONLY` is new; it only narrows a self-test run (nested runs use it).
5. Coupling: the guard reads `hack/check.sh`'s `run_gate` lines and `Taskfile.yml` through `task`,
   as the spec requires.
6. Abstraction: none bypassed.
7. Debt for green: none; the spec's allowed look-alikes are the only exclusions.
8. Legibility: the perl parsers are dense; each has a one-line contract comment.

Easier: a later gate, task or checklist change is caught by name. Harder: the guard's parsing
rules constrain how 2.2 writes the contract.
