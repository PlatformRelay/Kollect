## Deviations from the task text

- C1b lives in `cmd/cli` (package `main`), not `internal/pipeline`: the exit mapping
  (`exitCodeForContext`) is in package `main`, and SCT-5's scenario is the process exit, so the
  test drives the real `collect` command (cobra, `runCollectPipeline`, `mapContextResultsToExit`)
  with the real `pipeline.RunAllContexts` behind a spy. It is L2 envtest like
  `TestPipelineCLI_collectAndWrite` and runs in `task test`; it skips without envtest assets.
- C2's Postgres case "a DSN without sslmode" is no longer an error: the 2026-10-19 decision
  (loop *Triage* R-post, `agent-context/decisions.md`) made unset sslmode with a CA mean
  `verify-full`, so that spec builds and dials. C2 uses the cases that still fail before any dial:
  explicit `sslmode=prefer`, `sslrootcert` with a CA, garbage PEM.
- C1a starts from the CLI's build steps with a stub export callback, not a hand-filled
  `collect.Store`: `withCLIBackend` returns before calling the callback when the backend build
  fails (`wire.go`), so the callback flag proves no export ran; C3 covers the store-backed export.
- C1a also checks the operator probe and GCS, and a `caSecretRef` holding garbage, beyond the
  task's two S3 specs.
