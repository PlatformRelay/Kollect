## Design notes recorded before the code

- **Defect chain for (a), verified 2026-10-07**: `ConfigFromSpec` returns a plain `fmt.Errorf`
  for every spec fault (config.go:170, engine `cli` among them). `NewBackend` (backend.go:26-29)
  passes it through unclassified → `RunExportEnvelope` (export.go:174) and `RunCleanupExport`
  (cleanup.go:188) re-wrap it as `kollecterrors.ClassifyAPI(fmt.Errorf(...: %w, err))`, whose
  default branch demotes it to Transient (`internal/errors/errors.go:137`) → `setSinkReachableFromExport`
  (sink_status.go:150) picks the transient reason → the sink requeues the deterministic fault
  forever. Exactly the B register finding #3.
- **Fix shape**: classify at backend construction (`git.NewBackend` wraps the `ConfigFromSpec`
  error with `kollecterrors.Terminal`, message unchanged — `ClassError.Error()` unwraps) and stop
  demoting an already-classified error at the two consumption sites. `ClassifyAPI`'s mapping is
  identical to `ClassOf`'s (NotFound/Invalid/BadRequest→Terminal, Forbidden→Forbidden, else
  Transient — errors.go:99-107 vs 132-138), so dropping the demotion call and keeping the `%w`
  wrap preserves every observable class (conditions via `setSinkReachableFromExport`'s
  `IsTerminal`, metrics via `ExportErrorReason`→`ClassOf`, export.go:352) while a pre-classified
  Terminal survives. Verified `ExportErrorReason` is `ClassOf`-based (export.go:341-359) — the
  label set is unchanged.
- **Scope guard on (a)**: the same construction fault also reaches `RunCleanupExport` through the
  same `acquireBackend` seam; the demotion line there is the identical one-line defect shape, so
  it is fixed in the same change (BEP-1's delete path reports cleanup failures through the same
  condition machinery). No other ClassifyAPI call sites are touched.
- **Design for (b)**: the tombstone-ageing loop moves out of `pruneStaleEntriesLocked` into
  `pruneExpiredTombstonesLocked(now)` (tombstones carry no backends, so it is mutex-only and
  Close-free) and the delete-eviction hook calls it under the mutex it already holds. No
  widening: the eviction path does not start pruning live entries for other keys (that stays the
  acquire path's opportunistic cycle, AR-11). Fresh tombstones are unaffected (both call sites
  pass the same `timeNow` seam).
- **(c) scope**: only the two lines B flagged (operator-image rationale line, pipeline-image
  sentence). The pipeline sentence's "over HTTPS" qualifier is dropped together with the stale
  `cli` mention in the same sentence; the replacement names go-git without narrowing the
  transport claim, which resolveAuthType does not support (ssh:// endpoints resolve AuthTypeSSH,
  config.go:178-199).
- **(d) reading**: the orphan is the EOF comment `# fanout-review raw leg transcripts (never
  committed)`; the exclusion it describes is the misplaced `**/reviews/**/*.err` line currently
  sitting under the Spec Kit scaffolding comment. Repair = pair the comment with the pattern,
  no pattern added or removed.
- **(e) reading**: the spec delta's new clauses (commit e01fa939: "whenever the copy retains a
  metadata section", "SHALL export the copy without the stamp", doc SHALL state the
  metadata-retaining requirement) are already pinned by
  `TestPruneResource_defaultIncludeCarriesNoStamp` + `TestPruneResource_noStampWithoutMetadata`
  (copy exported without the stamp when the include drops metadata) and
