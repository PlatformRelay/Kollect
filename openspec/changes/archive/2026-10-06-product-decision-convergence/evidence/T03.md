## Seam placement decision

The hook lives in `internal/sink`, not `internal/controller`, for one mechanical reason: the task
requires the test to pool "via the production acquire path", and that path — `acquireBackend` — is
unexported to `internal/sink`. From `internal/controller` the only way to pool a backend is the
full export envelope (builds real backends); from inside `internal/sink` the test calls the exact
function production calls (`export.go:170`, `cleanup.go:184`) and reads the pool map directly, as
every existing pool test does. `EvictBackendPoolForSink` is exported because the T08 `DeleteFunc`
is its caller; the fallback decision sits in the seam per proposal.md:129-130 ("The eviction hook
is defensive about the unknown-state shape: it evicts by UID, and falls back to
namespace/name only when the UID is empty"), so the T08 watch stays a thin unwrapper. The
signature `(types.UID, string, string)` is the spec-fixed shape: BEP-1 needs UID plus the
namespace/name fallback inputs, nothing more (a `client.Object` parameter would drag the
tombstone-unwrapping question — T08's concern — into the seam's contract).
