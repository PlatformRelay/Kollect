## Design notes recorded before the code

- **Engine-less regression fixtures** (the round-2 spec-set review's fixture warning): every new
  test constructs configs without the `Engine` field and uses string literals, never
  `kollectdevv1alpha1.GitEngineCLI` or `internal GitEngineCLI` — both are deleted by T09, and a
  new test referencing either would create exactly the fixture debt the review flagged. The 19
  existing fixtures stay untouched (T09 migrates them).
- **Routing observable**: at HEAD both routing paths (`exportViaCLI` and `exportRemote`) succeed
  end-to-end on `file://` remotes (probed 2026-10-07 on a seeded and an empty bare repo: engine-less
  export and `exportRemote` both landed files; both failing paths wrap a `git clone:` prefix), so no
  outcome-level test can distinguish *which* branch served a `file://` remote. The regressions
  therefore pin the unchanged **outcomes** through the public entry points with an engine-less
  config (export lands the file; delete retracts from the remote feature branch and leaves the
  target tip untouched; probe succeeds and a non-repo path fails with the probe's own
  `git ls-remote failed:` wrapper, not a go-git error). The internal branch condition
  (`isFileRemote(req.cloneURL) || cfg.Engine == GitEngineCLI`, export.go:125 / delete.go:107) is
  judged from T09's diff by the independent review, not by an outcome test.
- **KEX relative-order pin**: the test hardcodes today's eight names and asserts they appear in the
  offer as an in-order subsequence plus the two new names present. It deliberately does not assert
  "the existing eight are the first eight" — the delta's normative scenario ("Existing preferences
  are not demoted") and the task text both say "in their current relative order"; the block-first
  reading would over-constrain T09's ordering choice.
- **Red reason check**: each red assertion references only symbols that exist at HEAD
  (`validateGitSpec`, `ConfigFromSpec`, committed CRD YAML, `sshAuthMethod`/`publicKeysAuth`) and
  fails for its stated reason (the rejection or the algorithm is absent), not for a missing symbol
  — the API change is entirely T09's, so nothing is scaffolded here.
