## Learnings

- tooling: `go test -count>1` is rejected by the Ginkgo suites in `internal/controller` (config error, not a test failure) - the race gate for that package is `-race -count=1`, matching `hack/coverage.sh`. Future tasks in this loop should not burn a correction on `-count=2` for `internal/controller`.
- sensor: `TestExtractHotPathBudget` fails under full-package `-race` load and `TestRecordLabeledMetricSeries_CapsCardinalityDeterministically` under `-count=2` (both pass in isolation; the metric one fails at base too). When a race run over `internal/collect` shows either name, rerun that test alone before classifying.
- sensor: the controller test package has a package-level `ctx`; test-local `ctx := context.Background()` trips govet `shadow`. Name test-local contexts `bg` in `internal/controller`.
- tooling: the fake client returns NotFound for `Status().Update` on an object not registered with `.WithStatusSubresource(...)` (controller-runtime v0.24.1). Any test driving `updateStatus` through the fake client needs the status subresource registered.
- spec: `PruneResource` never reads `Prune.ScrubKeys` - the engine merges them into the `*Scrubber` (engine.go:266). For T06: a profile scrub rule reaches the stamp only through the scrubber argument.
