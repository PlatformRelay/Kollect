## Design notes recorded before the code

- **Rejected reading stays rejected** (T04 learning, loop.md): GTE-2's ordering is the
  relative-order reading; the KEX extension appends `mlkem768x25519-sha256` and
  `diffie-hellman-group16-sha512` after the existing eight (keeps "existing algorithms first"
  true too). No re-litigation.
- **Engine branch points removed, CLI machinery kept**: the surviving shared machinery
  (`exec_git.go`, `cli_env.go`, `export_file.go`, `connection.go` ls-remote probe) stays. After
  the branch-point removal (`export.go:125`, `delete.go:107`: `isFileRemote || Engine == CLI` →
  `isFileRemote`) the CLI delivery machinery serves `file://` remotes only — exactly GTE-1's
  "keeps using the CLI machinery they already use today, unchanged" clause, since file:// always
  took the CLI branch regardless of engine. The per-engine probe/delivery function pairs stay
  untouched (D5's "not converged here" Sweep-2 hoist).
- **`cfgNeedsCLISSH` dies with the engine branch** (cli_env.go:94-105): its first line is
  `if cfg.Engine != GitEngineCLI { return false }`. Post-convergence the CLI env is built for
  file:// (never ssh scheme, token auth) and the probe (an ssh:// endpoint resolves authType
  AuthTypeSSH in ConfigFromSpec, so `authType == AuthTypeSSH` covers it). The function reduces to
  a duplicate of the caller's condition and is deleted with its engine-shaped test.
- **CLI-mirror regression locks in `delete_mirror_regression_test.go` (9 fixtures,
  integration-tagged) are deleted, not migrated.** Their header states the premise: all of them
  need the persistent warm-mirror topology (non-file:// remote), which is what `Engine:
  GitEngineCLI` selected. Post-convergence the CLI delivery machinery is reachable only via
  `isFileRemote`, and file:// remotes get a fresh temp workdir per operation
  (`prepareMirrorWorkdir`, mirror.go:209-220) — the (CLI machinery × persistent mirror ×
  non-file remote) surface the locks pin no longer exists in production. Migrating them to
  file:// would make them vacuous (the header says the defects cannot reproduce there); forcing
  the CLI branch on a non-file remote is impossible without the engine field. The go-git twins in
  the same file (persistent mirror via go-git, still reachable) stay. Authority: task text
  "remove the engine branch points" + GTE-1 file:// clause + D5. Listed under Test changes.
- **Persisted `engine: cli` sink** (GTE-1 scenario 4, the round-2 spec-set review's requirement):
  rejection happens at backend construction (`ConfigFromSpec`), whose error must name `go-git`;
  the operator never deletes or rewrites the object. Covered by
  `TestConfigFromSpec_rejectsCLIEngineNamingGoGit` (the same code path an already-stored object
  hits at its next export build — admission never re-runs on stored objects, so construction is
  the operator-visible failure) plus the upgrade note.
- **Fixture count check** (task text says 19): grep at HEAD gives 18 `Config{Engine:
  GitEngineCLI}` occurrences in `internal/sink/git/*_test.go` + 1 `kollectdevv1alpha1.GitEngineCLI`
  fixture in `config_test.go` (`TestApplyGitSpec_engine`, the engine-mapping table) = 19. The
  mapping test's premise (engine mapping) dies with the field; its rejection half is already
  covered by T04's `TestConfigFromSpec_rejectsCLIEngineNamingGoGit` — the mapping test is
  removed, the rest migrated.
- **Golden drift** (T04 harness gap): `test/schema/golden/kollectsnapshotsink.spec.openapi.yaml`
  pins `[go-git cli]`; regen step = `make generate manifests` + `UPDATE_GOLDEN=1 go test
  ./test/schema/ -run TestCRDSpecOpenAPIFragments`; `task verify` covers CRD bases, RBAC,
  deepcopy and the chart-CRD copy.
- **No Claude leg**: the loop budget counts Claude review legs 0/0 and the task prompt forbids
  them; the per-task review legs are `DeepSeek-V4.1-Flash:diff,Qwen3.8-Flash-Next:diff`
  (implementation task, not evidence/docs-only).
