## Learnings

- tooling: in controller-runtime v0.24.1, `handler.Funcs.DeleteFunc` has NO error return
  (interface `Delete` is `func(ctx, event.TypedDeleteEvent[object], workqueue.TypedRateLimit
  ingInterface[request])`), and the workqueue type lives in `k8s.io/client-go/util/workqueue`
  — there is no `sigs.k8s.io/controller-runtime/pkg/workqueue` package. Verified against the
  pinned module's `pkg/handler/eventhandler.go`.
- spec: envtest CRDs enforce their validation contracts — `KollectSnapshotSink` requires
  `spec.type` from its enum (git/gitlab/s3/gcs); a fixture sink must carry a valid type and
  the test registry must register the factory under that exact type, and family sinks'
  common spec comes from `FamilySinkSpec()` (the reconcilers' accessor), not `sinkObj.Spec`.
- sensor: a mutation check is the cheap discriminator for "wiring" sensors — gutting the hook
  body (envtest spec) and adding an `UpdateFunc` (delete-only pin) each turned exactly the
  new test red, proving the pins bind to the claim; but verify the mutation actually applied
  (a silent `python3 -c` string replace no-op made a check look green) — `go vet` catches
  unused-import mutations; heredoc replaces with an applied-confirmation print for the rest.
- guidance: nats' backend self-heals on Close (`Close` nils `nc`/`js`; `Export` → `jetStream`
  re-dials), so any path that hands a Closed backend to a caller can leak a fresh connection
  per use — the pool's post-tombstone acquire hands the built backend to the caller OPEN with
  an owning release instead. Proposed to the owner as a note for future backend contracts
  (a backend whose Export re-dials after Close cannot be safely handed out closed).
- tooling: `TestRunCleanupExport_gitReleaseFailureIsRetried` is a count-order flake under
  `-race -count=2` full-package runs in internal/sink (one occurrence on this tree; isolated
  ×2 and full ×2 reruns green, no data race) — rerun before classifying, alongside the
  breaker-race lesson.
