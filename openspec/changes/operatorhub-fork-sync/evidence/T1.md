## Maintainability

1. Duplicates existing logic? No; the PR lookup and bundle code are untouched.
2. New abstraction without a second user? `preflight_forks`/`sync_forks` are used by the real and
   dry-run paths.
3. Hidden coupling? The guard's mutants anchor on literal lines of the script; a reword makes the
   self-test fail loudly ("sed anchor no longer matches"), not silently.
4. Error paths silent? No; every failure prints the fork, its state and "Nothing was written/pushed".
5. Portability? No bash-4-only syntax beyond indexed arrays (`${!arr[@]}`), which bash 3.2 has.
6. Test isolation? The bundle fixture lives in the test's own `mktemp -d` directory, reached
   through a relative path from the checkout (the script prefixes `BUNDLE_DIR` with its working
   directory), and the trap removes it; nothing lands in the repository tree.
7. Scope creep? No; target repos, PR body and soft-fail are unchanged.
8. Docs drift? RELEASE.md updated in the same change.

- Reviewer B (security and CI lens): APPROVE. P2s: the same race and wording; unreadable fork or

  fork 2 diverged with zero writes); the fixture lived under `dist/` in the repository tree.
  Confirmed the CFC-6 and CWS-6 wiring red in a scratch copy, and that the new `ci.yaml` steps
  contain no `${{ }}` expressions.

Fixes: five cases and five mutants (fork unreadable, compare unreadable, unknown status, merge
commit, refused sync); script comment and RELEASE.md reworded (never force-pushes, syncs only a
strictly behind fork, stops on `merge_type=merge`, with the race named); fixture moved to the
test's temp dir. The OFS-3 mutant was not added: a mutant that interleaves check and sync per fork
is the `diverged-accepted` shape seen from the other side, and `case_diverged_fails` already fails
on it by its write count.

Round 2, one fresh reviewer, on `3611626cf`: APPROVE. P2s: proposal and tasks still said "never
merged into" (fixed: wording only, so no further round); the `compare-unchecked` mutant also
rewrites the post-sync re-compare, which no case makes unreadable (known gap: that path still
fails closed through the `status != identical` check, so a push cannot follow); the
`fork-read-unchecked` and `compare-unchecked` mutants are killed by their message, because the
next check still fails closed (recorded in the tasks.md verification row).

Verdict: CLOSED-WITH-GAPS. Gaps: the live `merge-upstream` call is not exercised (a write to the
third-party forks; operator-owned at the next release, together with confirming that
`OPERATORHUB_PAT` carries the `public_repo` and `workflow` scopes); `task docs:verify` not run
locally (CI runs it); an unreadable re-compare after a sync has no dedicated case.
