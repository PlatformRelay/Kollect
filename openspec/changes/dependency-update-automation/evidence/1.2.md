## Design choices

- **Fixture, not the real files.** As in 1.1, `--self-test` writes known-good copies of every file
  the new clauses read, so it is green now and after sections 2 and 3 land:
  `renovate.json` in task 2.2's shape (`extends` exactly `["config:recommended"]`; top level
  `platformAutomerge` false, `automergeType` `pr`, `automergeStrategy` `rebase`, `rebaseWhen`
  `conflicted`; rules in order gomod group, `github actions`, the Renovate image rule
  (`matchPackageNames` `["ghcr.io/renovatebot/renovate"]`, `groupName` `renovate image`,
  `schedule` `["* * * * 1"]`, `updateNotScheduled` false, `automerge` false), `docker images`,
  the digest automerge rule (`matchManagers` `["devcontainer","dockerfile"]`, `matchUpdateTypes`
  `["digest"]`, `automerge` true, `rebaseWhen` `behind-base-branch`, `description`),
  `pinned build tools`, the helm rule on `matchPackageNames` `["helm/helm"]`, `go toolchain` (last
  group rule), node/python (last rule)); `.github/renovate-config.json` as today; a validator
  script with 0.5's argv; a docs page whose Renovate section names every T17 item, one per line.
  The fixture config passes the real validator in both modes and the fixture script validates
  for real (probe below), so the fixture is checked by the pinned tool, not only by the guard.
- **Reads.** Config values are read parsed with `yq -p json`: single values as compact JSON and
  compared to an exact expected string (a failed read prints nothing and so fails); row reads over
  every mapping of both files (`cfg_rows`, `rules_rows`) red the clause on a yq error instead of
  passing with no rows. Each TSV field carries a `=` prefix so an empty field does not collapse
  under `IFS=tab` (iteration 2).
- **T10** checks `extends` of `renovate.json` as exact JSON, every other mapping of both files
  (the global config's root included) for an `extends` key, and refuses any `dependencyDashboard`
  that is not boolean `true` (stricter than "is false": a string or `null` also reds).
- **T11** counts mappings with boolean `automerge: true` in both files; exactly one, at
  `renovate.json:/packageRules.N`, with keys exactly `automerge`, `matchManagers`,
  `matchUpdateTypes`, `rebaseWhen` plus optional `description`, `matchManagers` sorted equal to
  `["devcontainer","dockerfile"]`, `matchUpdateTypes` `["digest"]`, `rebaseWhen`
  `behind-base-branch`.
- **T12** checks the four top-level values as typed JSON, then every mapping of both files: the
  keys `platformAutomerge`, `automergeStrategy`, `automergeType`, `rebaseWhen` are allowed only at
  `renovate.json`'s root, and `rebaseWhen` also on a `packageRules` entry with `automerge: true`
  (its value is T11's); `ignoreTests` is refused everywhere, the root included.
- **T13** compares the sorted key list and the two values as exact JSON.
- **T14** passes when some rule with `matchPackageNames` exactly the image has a `groupName` that
  no other rule uses and is not `github actions`, a schedule of exactly one `* * * * D` entry
  (D 0 to 7), `updateNotScheduled` false, `automerge` false (absent fails), and an index after
  every `github actions` rule; otherwise it names each failing part.
- **T15** finds the rule with `matchPackageNames` `["helm/helm"]` and `groupName` `helm`, refuses
  any rule whose `matchDepNames` holds `helm/helm`, and requires the helm rule after every
  `github actions` and `pinned build tools` rule (both must exist).
- **T16** builds a scratch root per case: the tree's script under test, the fixture
  `renovate.yaml` with an implausible image `ghcr.io/renovatebot/renovate:0.0.1@sha256:a…a` (so a
  script that hard-codes the real pin fails), and the tree's two config files. A fake `docker`
  first on `PATH` records each argv (one argument per line) and exits with the next status of a
  list for `run` calls (0 for any other subcommand). Cases: a digest-less image (`:0.0.1`) must
  exit non-zero with no docker call at all; with the digest image and statuses `0 0` the script
  must make exactly two `docker run` calls and exit 0; statuses `1 0` and `0 1` must each exit
  non-zero. A `run` call is judged on the image (the first argument after `run` that is not an
  option or the value of a listed value-taking option such as `-v`, `-w`, `--network`,
  `--entrypoint`, `--user`; an unlisted value-taking option makes its value read as the image,
  which reds), `--rm` before the image, the command (`--entrypoint renovate-config-validator`, `--entrypoint=…`, or the first
  argument after the image, a path ending `/renovate-config-validator` allowed), one file argument
  (the mount prefix allowed, e.g. `/repo/renovate.json`) and the exact flag set: `renovate.json`
  with `--no-global --strict`, `.github/renovate-config.json` with `--strict` only. Mount,
  workdir and network are not judged (task text; 2.3 runs the real validator).
- **T17** reads the section from the first level-1 or level-2 heading naming `Renovate` to the
  next level-1 or level-2 heading (headings inside fenced code are ignored) and needs, per item, every pattern:
  `hourly`; `RENOVATE_TOKEN`; `dependency dashboard`; `auto-?merge`, `digest`, `dockerfile`,
  `devcontainer`; `gh workflow disable`; `gh pr update-branch --rebase`;
  `hack/ci/renovate-config-validate.sh`; `hosted Renovate App` and `unused|not used|not
  installed`; `since the last tag` and `release` (fixed strings exact, the others ERE ignoring
  case).
- **Self-test runner.** The cases now run in parallel, one copy each (`nproc` at a time), and
  print in table order; 148 cases took 136 s sequentially, 16 s in parallel. Judging is unchanged
  (listed under *Test changes*). Each case's subshell runs under `set -e` (it is not the left side
  of `&&`), marks itself passed on its last line, and a case that ends early is named as `did not
  complete`.
- **Three combined rows** (`T10+T13`, `T11+T13`, `T12+T13`): each mutant adds a key to the global
  config, which breaks T13's exact key set by definition; the row is judged by its first
  clause's message.

## Probes

Command line: `bash /tmp/dua-G2/probe-fixture.sh <worktree>`. It loads the guard's functions,
builds the fixture, runs the pinned validator (0.5's argv) on the fixture config, then the fixture
validator script with the real docker, then with a `bogusOption` added, then the guard's plain
mode on the fixture tree.

```bash
#!/usr/bin/env bash
set -euo pipefail
REPO="${1:?repo root}"
OUT=/tmp/dua-G2/fixture
rm -rf "${OUT}"
sed '/^if \[\[ "\${MODE}" == "self-test" \]\]; then$/,$d' "${REPO}/hack/test/renovate_policy_test.sh" >/tmp/dua-G2/guard-lib.sh
source /tmp/dua-G2/guard-lib.sh "${REPO}"
build_fixture "${REPO}" "${OUT}"
chmod -R a+rX "${OUT}"
IMG="$(yq eval '.jobs.renovate.steps[2].with["renovate-image"]' "${OUT}/.github/workflows/renovate.yaml")"
set +e
docker run --rm --network none -v "${OUT}:/repo:ro" -w /repo --entrypoint renovate-config-validator "${IMG}" --strict --no-global renovate.json; echo "exit=$?"
docker run --rm --network none -v "${OUT}:/repo:ro" -w /repo --entrypoint renovate-config-validator "${IMG}" --strict .github/renovate-config.json; echo "exit=$?"
bash "${OUT}/hack/ci/renovate-config-validate.sh" "${OUT}"; echo "exit=$?"
cp "${OUT}/renovate.json" /tmp/dua-G2/renovate.json.bak
yq -p json -o json -i '.bogusOption = true' "${OUT}/renovate.json"
bash "${OUT}/hack/ci/renovate-config-validate.sh" "${OUT}" 2>&1 | grep -E 'Invalid|bogus' | head -2; echo "exit=${PIPESTATUS[0]}"
cp /tmp/dua-G2/renovate.json.bak "${OUT}/renovate.json"
bash "${REPO}/hack/test/renovate_policy_test.sh" "${OUT}" | tail -1; echo "exit=${PIPESTATUS[0]}"
```

## Learnings

- sensor: a guard that looks for an expected value "anywhere in the argv" passes when the value
  sits in another position (the workflow's image as an argument of another image); judge argv by
  position, and add a decoy that puts the right value in the wrong slot
- tooling: a subshell on the left of `&&` runs with `set -e` off inside it; a background case
  runner must mark success from inside the subshell, not with `(…) && touch ok &`
- tooling: a TSV row from yq with an empty field collapses under `IFS=$'\t'` (tab is IFS
  whitespace); prefix every field with a non-space marker and strip it after the read
