### Design notes

- **`--user "$(id -u):$(id -g)"`** (0.5: the image's user, uid 12021, cannot read a mode-600
  file and fails closed with `EACCES`). In CI the checkout is world-readable, so the flag changes
  nothing there; locally it makes a restrictive umask or checkout mode irrelevant. Probe
  `mode600` below: both files and the root at mode 600/700 validate (exit 0). T16 lists `--user`
  among the value-taking options, so the guard judges the image position correctly.
- **The image is read from the workflow, not hard-coded**, so a Renovate image bump PR validates
  with the image it proposes; T16 runs the script with an implausible image to prove it.
- **No guard edits**: `hack/test/renovate_policy_test.sh` is unchanged in this group (*Test
  changes*: none).

## Learnings

- tooling: Renovate's branch config is the first sorted upgrade's config spread over the group
  (`generate.js:225-229`); only `automerge` (and a few lists) are recomputed over every upgrade, so
  a rule-level setting such as `rebaseWhen` can leak from one upgrade into a mixed branch
- guidance: a lint step placed after a guard step that is red by design (known red) never runs in
  CI; its CI row stays `not-run` until the guard is green, so put a new step's CI proof on the
  task that clears the last known red
