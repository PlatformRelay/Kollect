## Decision request (3.2, SPECIFICATION)

**Context.** CFC-3's tenant scenario says namespaced triples are covered by the rendered namespaced Role, and
only cluster-scoped triples (namespaces, tokenreviews, subjectaccessreviews, `kollectcluster*`) are listed
exceptions. The probe finds six namespaced triples the tenant Role does not grant: `apps/deployments` and
`cert-manager.io/certificates` get/list/watch. They come from the `KollectTarget` controller's markers
(`internal/controller/kollecttarget_controller.go:41-42`), i.e. workload GVKs the default samples collect, not
reconciler needs. `docs/examples/team-operator.md` ("3. Workload collection RBAC (team)") says the tenant Role
does **not** list/watch workload objects **by design** and tells the team to grant those per namespace (with a
Deployments example). So the spec and the documented design disagree. Both remaining paths are out of my
remit: adding the grants widens tenant-mode privileges against a documented decision (and a product doc must
change); adding exceptions the spec does not name is an allow-list widening.

**Options.**
- **A (Recommended)** — amend CFC-3's tenant scenario: besides the cluster-scoped triples, workload-collection
  GVKs (today `apps/deployments`, `cert-manager.io/certificates` get/list/watch) are listed exceptions with the
  reason "tenant mode leaves workload collection RBAC to the team (docs/examples/team-operator.md §3)". Keeps
  the documented least-privilege design; the guard still catches any new reconciler grant (kollect.dev, core
  secrets/events) missing from the tenant Role, and a new workload marker forces a reasoned exception line.
- **B** — fix the chart: add `deployments` and `certificates` get/list/watch to the tenant Role and rewrite
  team-operator.md §3. Widens every team install to read Deployments/Certificates in its namespace;
  contradicts the documented design and still does not cover other GVKs a team profile names.
- **C** — check tenant mode only for `kollect.dev` and core reconciler groups (no exceptions for workload
  GVKs). Smaller exceptions file, but the guard silently ignores a whole class of triples, which is what CFC-3
  exists to prevent.

## Learnings

- class: spec. A spec scenario that enumerates exceptions should be checked against the product docs' own
  "by design" lists before tasks are cut; here the team-operator guide predates CFC-3 and was missed.
- `helm template --show-only` errors when the named template renders nothing (clusterrole.yaml in tenant
  mode); render all and filter on `# Source:`.
- `python3 -I` loses the user-site PyYAML on this host; the repo's guards use plain `python3`.
