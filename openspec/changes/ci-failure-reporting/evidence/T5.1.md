## Design

- **One mutant, one case.** A plain run takes about 43 s, so 85 full runs would take about an hour.
  `CFR_SELFTEST_ONLY` (an anchored regex over case names, set only by `--self-test`) skips every
  other case: `select_case` is called by `build`, `store`, the oracle, the wiring and the
  self-wiring sections, and a skipped case's `ok`/`bad` print and count nothing, while its gh
  fake, builder, `yq` and copy work is skipped. A filter naming no case reds (`names no case`),
  so a mistyped filter cannot pass, and the no-op control runs every case unfiltered.
- **Judging.** `judge` copies a base tree (`.github`, `hack/{ci,test,release,lib,docs}`,
  `hack/install-zizmor.sh`) to one scratch copy, applies the edit there, refuses an edit that
  failed or changed nothing (`diff -r` against the base), runs the gate on the copy and requires
  a non-zero exit and a `FAIL:` line containing each expected message. The copy is removed after
  each mutant. Gate `cfr` is this test (filtered); gate `cws` is `ci_workflow_security_test.sh`,
  for the three CWS-2 mutants (tasks.md: the suppression scenario proved against the existing
  rule).
- **Edits derived from the tree.** `lit` replaces a literal that must occur exactly once; `rx`
  and `yqe` are anchored on shape, not on values (the colour is any 6-hex, the checkout pin any
  40-hex); `drop_comment_above` deletes the comment block directly above a line and probes that
  none is left; `gone` and `rmf` are the absence probes of the deleting mutants. A mutant whose
  anchor disappears fails as "the mutation step failed", never passes.
- **Placement: `lint`, not `tool-pins-selftest`.** The self-test took 3:28 here (load average
  about 8; 91 s user, 122 s system). On `main`, `lint` ran 11-12 min and `tool-pins-selftest`
  19-20 min (runs 38931256941 and 38926231781, `gh run view --json jobs`, 2026-10-16). The
  operator's 2026-10-16 ruling moved slow self-tests out of `lint` so lint's wall time stays
  bounded; this one leaves `lint` (about 15 min, **believed** from the local timing) still under
  `tool-pins-selftest`, so the PR's longest required job does not grow, while adding it to
  `tool-pins-selftest` would lengthen that job, the critical path, by the same 3-4 min. The
  tasks.md text names `lint` too. If `lint` ever becomes the longest job, the step moves to
  `tool-pins-selftest` with no other change (the self-wiring check is job-agnostic; CWS-6 accepts
  any required job).

## Harness gaps

- Self-wiring is a line check (review round 1, NOTE): a step-level `if:` or `continue-on-error` on
  the lint step is refused by `dist_ci_wiring_test.sh` (`STEP_KEY_ALLOWLIST=(name run uses with env

  satisfy CWS-6 (each mode in a required job). Verified by reading both, 2026-10-16; not re-proved
  by a mutant here.
- The filter is an environment variable: a CI step that set `CFR_SELFTEST_ONLY` would run a subset.
  CI's step is the bare command (pinned by the self-wiring check, `-Fx`), and the env of a lint
  step is pinned by `dist_ci_wiring_test.sh` (GATE-CIWIRING-02). **Believed** sufficient.

## Maintainability

1. New abstraction: one (`select_case`, a case filter); needed to keep 85 mutants under 4 min.
2. Duplication: the edit helpers mirror CWS-7's pattern in shape; no shared library exists for guard self-tests.
3. Hard-coded values: literals of the scripts' own code (a vanished literal fails loudly); no version or pin hard-coded.
4. Error paths: an edit that fails or changes nothing is a self-test FAIL, never a pass.
5. Test of the test: the no-op, bot-bump and filter controls.
6. Readability: each mutant is one `judge` line naming its source (G2/G3/G4 id) and its message.
7. Debt for green: none; no check weakened, no allow-list widened.
8. Scope creep: none beyond tasks.md 5.1.

Easier to change: a broken guard clause now shows in CI as a named mutant instead of only in evidence.
