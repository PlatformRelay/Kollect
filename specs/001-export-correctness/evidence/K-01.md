# K-01 — Oversize exports silently skipped by non-object-store sinks

**Verdict:** CLOSED
**Change:** `internal/sink/export.go` raises terminal `ErrSpillRequired` from the
`!shouldExportForSpill` branch; `internal/controller/per_sink_export.go` maps it
to `SpillRequired`; both inventory controllers map the aggregate total failure to
`SpillRequired` and leave the coalesce checksum unrecorded.

## Independent review

Fresh-context subagent review (diff-only) returned REQUEST_CHANGES with two MEDIUM
findings, both resolved:

- **M2 (resolved)** — `ExportErrorReason` labelled the new error `terminal`, so the
  documented `spill_required` metric never fired for the primary git-only scenario.
  Fixed by special-casing `ErrSpillRequired`; covered by `TestExportErrorReason`.
- **M1 (resolved)** — zeroing the per-binding ceiling for database/event sinks
  silently voided it. Fixed by a nil-safe `ExportCeilingExceeded` Warning event
  (`warnSoftCeilingExceeded`, covered by `TestWarnSoftCeilingExceeded`) plus docs.
  The export still sends the complete set, as the batch lock requires.

## Harness gaps

None for the changed surface. The pre-export gate remains skipped when a snapshot
sink is bound; the sink-boundary error is now authoritative, so a git-only oversize
inventory reports `SpillRequired` rather than `PayloadTooLarge` when the whole
payload exceeds the inventory ceiling. Both degrade; the metric label differs. Noted,
not a defect.
