## Trade-off recorded

A database/event binding whose complete payload exceeds the 1 MiB inline cap now
degrades with `SpillRequired` rather than being torn into parts (there is no spill
path for these families). This is the intended K-01/K-02 interaction and is
documented in the ADR/REQUIREMENTS rewrite.

The per-binding `maxExportBytes` is a **soft** bound for database/event sinks: it
cannot be enforced by partitioning without tearing the set, so the complete set is
exported and a nil-safe `ExportCeilingExceeded` Warning event records the overage
(`warnSoftCeilingExceeded`, `TestWarnSoftCeilingExceeded`) — resolving the
independent review's M1 finding. The batch lock ("postgres-only 500 KiB ceiling →
all rows survive") is preserved.
