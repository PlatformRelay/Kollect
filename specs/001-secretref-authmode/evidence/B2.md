## Harness gaps

- The guard is admission-only, as C-1 chose. A CR that predates the webhook fix, or an install with
  `--validating-webhooks-enabled=false`, is not re-validated. Cheapest future sensor: a resolve-time
  check in `sink.ResolveSecret` against the same allowlist (would also need the sink namespace).
- The allowlist is a flat list of target namespaces: any sink author can read allowlisted namespaces.
  Deliberate (C-1); recorded in `values.yaml`, `docs/security/security-architecture.md` and the spec.

## Maintainability

- Names describe intent (`ValidateSecretRefNamespaces`, `SecretRefNamespaceAllowed`); no magic numbers.
- The walk is a single readable function; each ref path is explicit, so adding a new backend ref is a
  one-line addition. Paths in errors match the CRD.
- `AuthDisabled` is now a single equality; `validateInventoryAuthMode` is a closed-set check.
- Coupling: the webhook imports `validation` exactly as it already did for spec/scope validation.
